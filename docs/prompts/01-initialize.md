# 首次开发提示词

将下面正文复制给 Cursor 或 Codex；本文件是启动任务，不是 shell 脚本。

---

请在当前 `qualityoffice-ai` 项目中完成开发初始化，并开展 W00-1。不要一次实现后续产品功能。

先读取适用的 `AGENTS.md`、`docs/START-HERE.md`、`docs/progress.md`。定位有效开发基准目录，读取 README、开发Spec 第1—4节及第17—18节、tasks.json 中 W00-1 和 test_cases.json 中 TC-001—TC-003。根据需要查发行清单、决策门槛和其余相关文件。

请先检查当前真实环境：目录内容、是否已有 Git 和 dsh 源码、分支与未提交改动、操作系统和上游要求的工具。报告实际加载的规则文件、规格位置、当前目标和验证方式，然后推进已授权的可逆工作。

具体目标：

1. 核对基准文件完整性和版本；保留已有文档与用户改动。基准结构检查和真实源码/应用测试分别记录。
2. 如果已有 dsh 派生仓库，记录上游 remote 和 commit，保留其历史、AGENTS 和工程配置。如果当前只有文档，先据真实官方仓库确定保留历史的派生方式；在临时位置准备源码并合并资料，不能清空当前目录或对非空目录直接 clone 到 `.`。需要现有远程地址/访问而无法取得时，记录具体缺口，继续不受影响的资料和本地检查。
3. W00-1 记录真实候选 40 位 commit、锁文件、候选插件的来源/commit/engines、运行依赖与资产、许可证和分发要求。查实际源码/说明，不猜 API 和兼容性；未知项保留未验证状态。
4. 按真实源码确认安装、启动、检查和构建命令及工具版本。保留上游已有配置，只补当前初始化必需部分；此轮不预先搭建整个产品前后端、不配置生产密钥、不展开知识库/资讯/办公功能。
5. 原开发基准资料接入正式源码时可整体放 `docs/spec/`，保留内部相对结构；更新入口和进度。整理并记录需要的忽略规则、环境变量占位示例和最小检查方案；仅在确定真实依赖后添加配置，不覆盖已有上游文件。
6. 执行当前环境可运行的检查，按工作包要求验证 TC-001—TC-003。需要 Windows、外部访问或资产而未执行的项目明确列出；未满足门槛不得标记完成。
7. 根据 `docs/templates/work-package-report.md` 保存实际报告，更新 `docs/progress.md`。报告包含任务范围、修改文件、上游候选、实际命令与结果、未验证项、阻塞和下一步。

此轮交付：可追溯的工程状态与 W00-1 证据/缺口清单。只有 W00-1 完成后，才按后续任务指令进入 W00-2；不要把生成模板、文档校验或 Linux/WSL 检查写成真实 Windows 验证通过。
