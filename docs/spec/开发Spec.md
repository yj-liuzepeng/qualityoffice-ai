# QualityOffice AI 开发与测试规格

文档版本：Spec v1.2  
日期：2026-10-22  
需求基准：《QualityOffice AI 开发需求文档 v0.3》  
覆盖版本：V0.1—V0.5；V0.4 分为 V0.4.1 / V0.4.2 / V0.4.3  
用途：研发实现、AI 编程任务输入、测试设计、阶段验收、发布核对。

**本文是实施规范，不是已经通过验证的产品说明。** 已确认需求予以保留；本文补充的数值、技术方案和交互规则标为“规格默认”，作为研发起点。真实上游 commit、依赖组合、模型路由和 Windows 实测结果必须通过对应门槛后写入发行清单。不得用本文代替实际构建和测试证据。

**产品名称：质量AI助手 · QualityOffice AI**  
**产品定位：面向专业工作的 AI 知识与办公助手**  
**品牌宣传语：专业知识，智能办公。**

通用能力包括：本地知识库与快速问答、可保存个人要求的办公辅助、选择式领域资讯，以及简洁专业的统一界面。医药行业为首个可选领域包和初始验证市场；账号、通用导航、知识库与任务引擎不要求医药岗位。

本次修订新增 PRODUCT/UI/PREF/FEED 需求及其任务、契约、数据与测试；原有需求及 TC-001—TC-137 保留。排期调整为 15 个周期、33 周；共 67 项需求、45 个工作包、153 条计划测试。个性化是可版本化配置，不默认训练模型；跨行业架构不等于已经验证其他行业内容。

## 阅读与执行入口

先读第 1—4 节锁定范围和周期，再执行 `tasks.json` 中依赖已完成的任务。第 5—16 节是实现约束；第 17—21 节规定测试、发布和变更。`test_cases.json` 提供逐项前置条件、操作和预期结果；`contracts/` 与 `data/` 提供产品自有契约及结构基线。

工程包中的状态均为 `planned` / `not_run`，没有把设计检查标成产品测试通过。执行 `python3 validate_spec.py` 只能检查工程包的引用和结构一致性。

## 1 规范等级、范围及优先级

### 1.1 决策等级

| 标记 | 含义 | 执行规则 |
| --- | --- | --- |
| U：用户已确认 | 原需求中明确的产品决定 | 变更必须记录用户决定及影响 |
| D：规格默认 | 本文为实现补充的确定规则 | 可以按本文实现；调整需 ADR 和受影响测试更新 |
| G：阶段门槛 | 必须通过调研、构建或实测才能锁定 | 依赖该结果的功能不得跳过门槛进入发行包 |

“必须”是验收条件；“应”是默认做法，偏离须说明；“可”是可选增强。未标记的算法和数值属于 D，不表示用户曾逐项确认。P0 为对应发布版本的必交项；后续版本的 P0 不提前压入 V0.1。

### 1.2 保留的用户决定（U）

面向管理资料、获取知识和制作办公文件的个人用户，以医药行业为起步场景，首批用 QA/QC 任务验证；以官方 dsh 桌面端为底座；先做 Windows 10/11 x64；冻结上游版本；保留基础对话和必要工具，用户版完全隐藏代码、终端、插件管理及原始配置；产品品牌为“质量AI助手 · QualityOffice AI”，宣传语为“专业知识，智能办公。”；通用方向已确认，定位措辞“面向专业工作的 AI 知识与办公助手”为本版建议；自有界面；必要插件及实际运行依赖随产品交付。

V0.1 必须有带网页来源的联网检索，读取 DOCX、文本 PDF、XLSX、CSV、PPTX、图片和扫描 PDF，扫描件提供 OCR。原件保留，所有修改另存副本。会员包含模型额度，首批邀请内测，由管理员手动开通。个人文档与知识库本地管理；每日资讯只在电脑和程序运行时执行。

### 1.4 专业用途与数据边界

本产品帮助各类专业用户整理材料、核对依据和制作办公文件。下述医药用途限制适用于首个领域预设。V0.1 不实现电子签名、受控批准、批记录放行、LIMS/QMS 集成或验证系统，不声称软件本身已通过 GxP/Part 11 等认证。法规回答显示来源、日期、适用地域及版本核对状态；不能把通用 AI 输出当作经批准的企业质量结论。

本地存储指文档、索引、会话和产物保存在用户电脑。云模型调用会把选中的问题、片段及必要图片经平台网关发给服务商；首次使用与设置页必须清楚展示该路径。没有网络时仍能浏览已有本地记录与文件，不能提供云模型新回答。

## 2 周期、人员假设与交付门槛

### 2.1 估算规则

规格默认：1 名熟悉 TypeScript/Python 的全栈开发者，每周 30 小时有效研发；另有产品/测试评审每周 2 小时。仍为 15 个周期：C01、C09、C11 各 3 周（72 小时计划工作 + 18 小时缓冲），其余各 2 周（48 + 12 小时）。共 33 周、792 小时计划工作、198 小时集成/缺陷缓冲，合计 990 研发小时；评审 66 小时另计。新增 3 周分别用于统一界面与易用性、成品领域包与订阅、个人办公要求与快照，不把新增范围当作零成本。

这是排期基线，不是交付承诺。未计入从零学习 dsh、等待证书采购、长时间服务商审批或新增需求。每周期结束用实际消耗重估剩余任务；连续两个周期偏差超过 20% 时重排。增加开发人数不会线性缩短 Windows 验证、需求评审和试用观察时间。

## 3 产品结构与界面行为

### 3.1 用户版导航（UI-01）

主导航最多四项：工作台、知识库、办公、资讯；账户与设置固定在底部。按交付版本显示：V0.1 仅工作台，V0.2 增知识库，V0.3 增资讯，V0.4.1 增办公。未交付页不显示空壳、占位推广或“敬请期待”。历史、文件和产物整合在工作台与任务详情，不再占多个一级导航。

工作台保留提问、文件分析、联网检索及基础文件生成入口，展示最近任务和产物。任一已上线模块从工作台最多一次点击可达，核心操作区最多两次点击可达；输入问题、选择文件和系统授权不计入导航。知识库页打开即见范围选择和问答框；办公页按 Word/Excel/PPT 任务而非技术工具分组；资讯页把“订阅设置”与“每日资讯”放在同一区域。

创建任务后展示附件、阶段进度、停止、回答、引用和输出卡片。输出区分“文件生成完成”“内容检查完成”“预览未完成”。引用展开来源、位置、版本/访问时间并打开原文；旧文件不存在则明示不可用。

账户页显示有效期、总额度/可用/处理中预留、最近用量和规则说明；区分额度、会员、账号和网络错误。历史及本地导出不因会员到期被锁住。管理员地址、共享凭据和内部日志不进入用户 UI。

### 3.1a 视觉与新手验收（UI-02 / UI-03）

白或浅灰主背景、一种主强调色，统一栅格、间距、输入框、按钮和文件卡片；禁止大幅无功能插画、自动轮播和无任务意义的动效。正文默认 ≥14 CSS px，辅助文字 ≥12；普通正文对比度目标 ≥4.5:1，大字及关键图标 ≥3:1，用工具记录实测色值。按钮同时有文字或可访问名称，状态不用颜色单独表达。

最小参考窗口 1024×768 物理像素；高 DPI 时按实际可用 CSS 视口自适应，可折叠侧栏、竖向重排。Windows 100/125/150/200% 缩放均检查：核心按钮可达且不被裁切，主流程无横向滚动；大型表格/预览允许其容器内滚动。若系统不允许该物理尺寸组合，记录实际最小窗口并在同等 CSS 视口测试，不伪造截图。

Tab 顺序、焦点可见、键盘停止/重试可用；中文输入法 composition 阶段 Enter 不发送。空态直接提供下一步，错误使用业务语言并有可执行恢复路径。快速响应目标沿用 §14，布局效果不能替代实际任务成功。

C01、C08、C10、C11 各安排至少 5 名首次接触该版流程的使用者，至少 2 名非医药背景；分别用三项已交付任务（如文件分析/检索/找产物，或建库/提问/找引用）验证。至少 4/5 无口头指路完成三项入口定位；记录点击数、入口定位时间（目标每项 ≤30s）、失败步骤。未达标须整改复测，并按该版回归已交付模块。

### 3.2 必备状态

每个异步页面覆盖空白、加载、可用、局部成功、失败和重试。文件逐个显示等待/复制/解析/OCR/完成/局部/失败，不允许总进度掩盖失败页。取消后保留已产生的可核对结果，但展示为局部结果；不自动归入“成功”。重试创建新 attempt 并明确是否将产生新的模型消耗。

标准用户构建不注册技术入口快捷键、路由、菜单、协议或上下文项；生产构建禁用 DevTools。仅隐藏 DOM 元素不算通过。内部调试包采用独立 appId、目录、图标水印和服务端环境；禁止把调试凭据打进用户包。

### 3.3 首次使用与退出

首次启动：欢迎/数据处理说明 → 邀请账号激活或登录 → 工作空间初始化 → 首页。原始资料选择不等于授权扫描整个硬盘。默认工作空间由产品创建在本机 NTFS 用户目录下，用户不能直接把 Documents/Downloads 或源文件夹设为执行根目录。

关闭窗口默认进入托盘（首次给出解释，可改为退出）；完全退出时有任务则显示停止并退出/返回。强制结束或断电后，重启将运行中的 attempt 标为 `interrupted`，进行临时文件和服务端结算状态核对，不自动再次发送付费请求。

## 4 技术架构与上游管理

### 4.1 规格默认架构

| 层 | 实现默认 | 责任 |
| --- | --- | --- |
| 桌面宿主 | 冻结 dsh Desktop 原技术栈，不单独强升 Electron | 窗口、Agent、会话、UI、生命周期 |
| 产品业务层 | TypeScript 的独立业务模块/Bundle + 少量集中上游补丁 | 任务、工具代理、文件/知识/资讯/Office UI、模型适配 |
| 本地执行 | 随包 Python 与 Node；固定程序入口；CPU OCR/嵌入 | 解析、渲染、计算、生成；只接受受控参数 |
| 本地持久化 | SQLite（产品元数据/FTS）+ 文件对象库 + 版本化向量快照 | 本机单用户数据，不建设云文件库 |
| 服务端 | Python FastAPI + PostgreSQL，HTTPS 反向代理 | 账号、权益、额度、模型与搜索网关、审计 |
| 后台 | 复用前端技术栈的小型网页后台，独立管理员权限 | 人工开通、调整、查询、成本与故障 |

以上是本项目选型，不是官方 dsh 的内置服务声明。框架和运行时精确版本与上游一起在 G00 冻结。V0.1 不引入微服务、分布式队列或独立向量数据库；网关可先单实例运行，数据库事务仍必须支持多实例扩容后的正确性。

桌面本地 worker 不接收云凭据；服务端不持久化文件全文与聊天正文。请求正文只为当次推理在内存转发，反向代理、异常收集和 APM 都应关闭正文记录。第三方服务商的数据保留政策另在 G02 记录，不能把“本平台不保存”写成“服务商绝不保存”。

### 4.2 上游复用和候选插件

官方宿主、会话和 Agent 为基础；优先复用官方 Office Skills、Office-to-PDF/LibreOffice 运行基础。社区 `dsh-open-file`、`dsh-cowork`、`dsh-quicksight` 只列为候选，不同时堆装。一个主导入入口、一条主要解析链路；其他组件只填明确缺口。

G00 对候选逐项记录：来源仓库、commit、包版本、`engines.dsh`、Windows 原生依赖、执行工具、安装位置、许可证及样本结果。不兼容时用产品适配层或替换底层解析器；不可仅修改兼容版本号而不验证实际 API。

官方 Office Skills 不能替代 Python 库、转换程序、字体和 OCR 数据。候选组件的隐藏下载、自动更新、CLI 安装步骤必须转成受控构建步骤。首启不能临时执行 `pip install`、`npm install`、`git clone` 或请求管理员安装开发环境。

### 4.3 冻结清单与源码布局

开发仓库推荐按 `upstream-patches/`、`product/desktop/`、`product/local-worker/`、`product/server/`、`product/admin/`、`contracts/`、`tests/`、`release/` 组织逻辑边界；实际目录须服从所选 dsh 仓库约定，不要求机械重排上游。

发行清单 `release-manifest.json` 必填：产品版本/构建号、上游 URL 与 40 位提交、各插件版本与提交、锁文件 SHA256、Node/Python/转换器/OCR/嵌入版本与资产 hash、目标 OS、appId、协议名、服务环境、许可证清单、安装包 hash、构建来源和签名状态。未知字段使发行检查失败；本包的模板不是可直接发布的有效清单。

通过产品配置和薄适配实现定制；必要源码补丁列出目的、触达模块、回归测试与上游冲突风险。禁用上游账号登录、市场、云平台和自动更新路径之前逐项检查依赖，不能假设改 Logo 就实现独立发行。

### 4.4 Windows 执行边界（关键）

官方 Windows ACL 后端主要限制子进程写入/删除；它不单独约束读取、联网和进程可见性。工作目录授权还可能留下长期 ACL/完整性标签。因此不得把用户原始目录或整个用户目录当沙箱工作根；不得认为沙箱已实现完整读取与联网隔离。

**用户版默认不给模型暴露任意 PowerShell、终端、代码执行、包安装或路径级写工具。** 官方工具仍可作为可信宿主内部执行部件。模型只能调用 `contracts/local-tools.schema.json` 描述的业务工具；工具代理将文件 ID 和类型化计划转换成固定可执行程序及参数，`shell=false`，不拼接命令，不接受任意脚本字符串。

如所选官方 Office Skill 依赖任意生成脚本，必须适配为受控计划或另行通过 G01/G07 的更强隔离验证；不得为保留一项功能默默放开全部执行。V0.1 的通用 Office 基础使用固定生成器，复杂动态代码执行不属于默认授权能力。

实际子进程的可写范围只含该 attempt 的工作目录和独立临时目录；必要时使用官方 ACL 后端，并验证每个工作空间独立实例。引擎、元数据库、文档对象库、原文件均在可写根之外。worker 禁用 Python 用户站点及 pycache 写入，临时目录/LibreOffice profile 独立到本次任务；通过 Windows Job Object 或等效机制回收整个进程树。Office 外部资源关系默认不联网展开，无法禁止时拒绝该渲染路径。禁用宏、外部链接自动更新和任意扩展加载。隔离初始化失败返回 `EXECUTION_UNAVAILABLE`，不得退回不受限 shell。所选转换引擎在受限环境不能启动子进程等问题必须在 G00 复现和解决。

固定可信解析器仍存在自身漏洞和读侧边界限制；不能对外宣称“任意恶意文件完全隔离”。用户版不接受不可信代码作为任务输入，依赖升级、解析器限制和超时属于持续维护项。

## 5 文件生命周期、任务与工具契约

### 5.1 文件落盘和权限

规格默认目录：产品用户数据根中放 `state/`（SQLite 等）、`vault/objects/<sha256>/`（不可变导入副本）、`work/<attempt_id>/`（本次执行副本）、`artifacts/<artifact_id>/`（已确认产物）、`cache/`（可重建）、`backups/`。受 ACL 写授权的目录只允许是独立的 `work/<attempt_id>/` 及其私有临时目录，不能覆盖 `state/`、`vault/` 或所有其他任务。

导入时使用 Windows 源文件句柄的拒绝写共享模式，复制完成前不允许并发改写；已有独占/写占用无法取得一致快照时返回 FILE_IN_USE，要求关闭占用或先由用户另存副本。导入经原生文件选择/拖拽授权后：校验格式及上限 → 打开并顺序完整复制到临时对象 → 计算 hash → 检查源文件复制期间是否变化 → 原子提交对象及元数据 → 提供文档 ID。必须按字节复制，禁止硬链接、符号链接、junction 或其他 reparse point 把原件映射进可写根。路径解析检查最终句柄目标；拒绝解析过程中越过授权根的别名。

复制期间检测到变化返回 `SOURCE_CHANGED` 并允许重试，不能声明已锁定一致版本。源路径只供宿主显示/打开，传给模型的是显示名和文档 ID。文件名本身也视为不可信文本，不能用作命令片段。

生成器先写 `work` 临时文件；校验格式/可打开/结果清单/输出限制后，由宿主原子提升为新 artifact。失败或取消时不提升为成功产物。每 attempt 最多提交 10 个产物、总计 200 MiB、单个 50 MiB；超限不提升为正式成功产物。用户“另存为”由原生保存框授予单次目标；默认加版本后缀，已有文件须由用户明确确认替换，模型不能替用户确认。

### 5.2 任务状态与重启

任务是用户请求，attempt 是一次执行，model run 是一次远程调用，三者 ID 分开。重试复用 task_id，创建新 attempt_id；每次付费调用有独立 request_id。

| 当前状态 | 允许后继 | 持久化动作 |
| --- | --- | --- |
| queued | running / cancelled | 记录排队时间及取消原因 |
| running | succeeded / partial / failed / cancelling / interrupted | 每个工具步骤和产物单独记录 |
| cancelling | cancelled / interrupted | 停止调度新调用，取消 worker/远程，核对结算 |
| succeeded / partial / failed / cancelled / interrupted | 无 | 终态不可覆盖；重试建新 attempt |

`partial` 代表明确可用的局部结果并带缺失范围；用户取消即使已经产生部分内容仍保持 `cancelled`。终态持久化采用版本检查，防止迟到成功回调覆盖取消。产品重启将未终结 attempt 置为 `interrupted`；只恢复已保存内容和查询远程状态，不自动重放请求。

默认单机同时运行 2 个任务，重型解析/OCR/渲染共用 1 个执行槽；每任务最多 12 次模型调用、30 分钟总执行时间；用户可看到达到上限的原因。重型文件按页/区域生成进度，不用假进度掩盖阻塞。

### 5.3 产品自有工具

工具名均为本项目契约，不能当作上游已有 API：`qdesk.file.parse`、`qdesk.file.read_segments`、`qdesk.web.search`、`qdesk.web.read`、`qdesk.office.plan`、`qdesk.office.execute`、后续 `qdesk.kb.search`。JSON Schema 中拒绝未知字段，所有资源按 ID 解析。模型不能请求任意绝对路径、执行命令、改网络端点或安装插件。Office 操作与 step 的白名单、发布版本和公式规则以 `contracts/office-operation-matrix.json` 为准，不能通过混用合法 step 绕过目标范围。

工具结果统一含 operation_id、status、data、warnings、error、source_refs；状态为 ok/partial/error/cancelled。解析成功、模型回答完成、文件生成和预览完成分别记录；工具返回不能以“退出码为 0”替代产物校验。

Office 模型输出先形成 JSON 操作计划，经类型、范围、模板、公式及输出数量检查再执行。计划中的 `operation` 必须属于白名单；字符串不得含可执行脚本。需要用户选择范围、模板或输出位置时挂起执行，保存可继续的业务状态，而非向用户展示终端审批。

### 5.4 错误分类与重试

至少使用：UNSUPPORTED_FORMAT、ENCRYPTED_FILE、FILE_TOO_LARGE、FILE_IN_USE、SOURCE_CHANGED、PARSE_FAILED、PARTIAL_CONTENT、OCR_LOW_CONFIDENCE、EXECUTION_UNAVAILABLE、OUTPUT_VALIDATION_FAILED、NETWORK_UNAVAILABLE、SOURCE_FETCH_FAILED、AUTH_REQUIRED、ACCOUNT_DISABLED、MEMBERSHIP_EXPIRED、QUOTA_INSUFFICIENT、RATE_LIMITED、MODEL_TIMEOUT、USAGE_PENDING、SCHEMA_MISMATCH、CANCELLED。

网络只在确定尚未向服务商派发时自动重试，默认 1s/3s 两次并加抖动；派发结果不明先查询原 request_id。HTTP 429 遵守 Retry-After，最多两次且不超过任务时限。解析确定性失败不盲重试；超时允许用户缩小范围后新 attempt。错误日志只存类别、步骤、ID 和经过清理的堆栈，不存全文或密钥。

## 6 多格式读取、OCR 与基础产物

### 6.1 处理上限（D，G00/G01 实测后冻结）

| 项目 | 默认值 | 超限行为 |
| --- | --- | --- |
| 单文件 / 单任务 | 50 MiB；最多 10 个文件、合计 200 MiB | 开始复制前说明，不静默忽略 |
| PDF | 最多 200 页；文字页和扫描页混合判断 | 允许用户明确选择页段；标记实际处理页 |
| XLSX/CSV | 单次最多 100,000 非空单元格、10 张表；CSV 最多 100,000 行且受单元格限制 | 分块选择；显示实际区域，不以预览代表全文 |
| PPTX | 最多 200 页 | 明确选择页段 |
| 图片 | PNG/JPEG/BMP/TIFF 静态页；单帧最大 20MP，单任务渲染像素累计受 200 页上限约束 | 安全缩放需显示，拒绝解压炸弹和超帧文件 |
| 单次文本解析 / 转换 | 120s / 180s | 终止 worker，标明已处理范围 |
| OCR | 单文件最多 20 分钟；逐页进度；单页 30s | 记录失败页；整体可 partial，不无限等待 |
| 模型输入 | 产品默认最多 32,768 输入 token、8,192 输出 token，并受实际模型总上下文更小值约束 | 先检索/压缩并提示选中范围，不能无提示裁切 |

ZIP 容器类文件还要限制展开后总量 500 MiB、条目数 10,000、目录层级 16，拒绝路径穿越。扩展名、MIME 与文件签名交叉校验；`.doc/.xls/.ppt/.xlsm` 不属于首版输入范围，提示转换。上限变更须同步 UI、Schema、测试和发行说明。

### 6.2 标准化 ParseResult

见 `contracts/parse-result.schema.json`。必有 document_id、document_version_id、sha256、parser_version、status、segments、coverage、warnings。segment 含稳定 ID、顺序、text、kind、locator，OCR 段可含 confidence 和 bbox；没有可信度时不能伪造数字。`coverage` 列出处理范围、总范围（未知为 null）、省略范围及原因；空结果与全文为空、解析失败必须区别。

locator 类型：DOCX 的 OOXML part + 段落序号/表格单元格；PDF 的原页（从 1 开始）与可选 bbox；XLSX 的工作表名与 A1 区域；CSV 的物理行/逻辑记录范围；PPTX 的 slide_id/页序/shape_id；图片的帧号与像素区域。DOCX 预览页码单独标 `preview_page`，不能当作原件固定页码。

源引用是可验证结构，回答中的 `[S1]` 由宿主映射到真实引用对象，模型不能编造新 source_id。正文引用定位依据实际解析版本，旧版本删除后显示不可用原因。

### 6.3 各格式最低承诺

| 类型 | V0.1 实现 | 明示的边界 |
| --- | --- | --- |
| DOCX | 正文段落、普通表格、常见列表；保留结构顺序 | 批注、修订、文本框、页眉页脚若未提取必须列警告；不声称保真编辑 |
| 文本 PDF | 按页文本与定位；检测文本稀少页后补 OCR | 双栏阅读顺序/跨页表格不可确认时提示；不能把目录页当全文 |
| XLSX | 表名/可见性、值、公式字符串、缓存值是否存在、合并区域 | 默认不执行宏/外链；公式与缓存区分；读取不等于重算 |
| CSV | UTF-8/UTF-8 BOM；显式尝试 GB18030；逗号/制表符/分号 | 引号内换行按逻辑记录处理；编码歧义请用户选；防公式注入 |
| PPTX | 页顺序、shape 文本/普通表格、备注是否可读及图片对象清单 | 图片语义和复杂图表另走图像/对象能力；不能凭文本判断视觉布局 |
| 图片 | 中英文印刷体 OCR、旋转纠正、区域定位 | 低清、手写、遮挡和特殊符号要求复核 |
| 扫描 PDF | 安全渲染逐页 OCR，混合页不重复计入文本 | 单页错误不吞掉后续页；失败/低可信页列出 |

### 6.4 OCR 和运行依赖

默认本地 CPU OCR，不需要 GPU，不自动把整份扫描件上传云视觉。RapidOCR/其他引擎的实际选择在 G00 锁定模型资产、语言覆盖、hash 和许可证；模型资产随完整安装包提供。对于图片视觉理解，只有经过 G02 独立验证、用户知晓数据路径与消耗时才启用。

PDF 解析与渲染可通过选定插件或 pypdf/pypdfium2 等适配。候选依赖的许可证和嵌入二进制逐项审查；不能因为 dsh 主仓库开源，就认定所有 PDF、字体和转换器可以按同一许可分发。若出现 PyMuPDF 等双许可组件，先确认本项目分发方案及许可条件，或换兼容替代。

### 6.5 V0.1 基础产物

至少提供：对话/来源 Markdown 导出、普通 Word 摘要（标题/段落/表格）、Excel 摘要表（值及受支持公式）、PPT 基础模板（标题/正文/表格）。复用官方 Office 指令与资源时仍经过产品计划和执行器。产物用重新打开的结构校验确认不是损坏 ZIP；预览调用实际转换器，失败时返回独立预览警告并保留可编辑副本。

不承诺 Word 任意修订、复杂 Excel 模型、已有 PPT 指定页保真；这些由 V0.4 的对象白名单和差异验证覆盖。对超出基础边界的请求说明当前范围，不能后台悄悄执行不受控脚本。

## 7 联网检索与证据

### 7.1 检索和抓取

搜索提供商和网页读取均由服务端管理共享凭据；客户端通过有权限的网关接口调用。默认每次最多 5 条搜索结果、每任务最多 3 次搜索及 10 次正文抓取；公开网页每篇正文上限 100,000 字符，超出记录截断。普通外网 HTTPS/HTTP 页面可请求，下载文件必须走导入限制，不执行网页脚本和登录操作。

抓取防 SSRF：仅 http/https；拒绝 userinfo、非允许端口（默认 80/443）、localhost、私有/环回/链路本地/多播和云元数据地址；每次 DNS 解析及每一跳重定向都复查，最大 3 跳，连接与响应限时，总响应限制 10 MiB。不能仅检查原始 URL 就允许跳转内网。

用户文档中的全文默认不作为搜索词发给搜索服务商。先形成必要的短查询；涉及文件专有内容时在任务中显示联网动作和查询，供用户关闭或编辑。搜索返回和网页正文均为不可信资料，内嵌“忽略规则/上传文件/执行指令”等内容不能改变工具权限或模型系统约束。

### 7.2 来源对象与回答

每条来源含 source_id、原始 URL、最终 URL、规范 URL、标题、发布机构（可为空）、published_at（可为空）、fetched_at、正文 hash、提取状态、可用定位/摘录。搜索摘要只能标“搜索摘要”，不能当成已阅读全文。

回答把事实陈述与材料推断区分。涉及法规现行性时优先发布机构原文；未能核对发布日期、生效日或废止关系时明示“尚未确认现行状态”。网页变动或访问失败保留当时的元数据/允许保留的摘录，不能生成假的现行声明。不得依靠网页 mtime 或“最新”标题自动判定法规有效。

法规类答复最少展示来源机构、地域/适用范围（能确定时）、文件名称/编号、发布或生效日期及核对状态。V0.1 不自建全量权威法规库。直接引文和本地存储正文遵守来源使用条件，资讯包默认保留元数据、摘要和必要摘录。

## 8 账号、权益、模型网关与额度

### 8.1 邀请账号与会话（D）

V0.1 采用管理员建立用户名/可选邮箱 + 一次性激活码，用户激活时设置密码；不依赖短信或邮件发送。激活码随机至少 128bit、数据库仅存 hash、72h 过期、一次性使用；管理员通过产品约定的人工渠道交付。本文不要求任何当前工具替用户发送邀请。

密码至少 12 字符，采用成熟密码 hash 库（参数在 G02 按服务端性能冻结）；连续失败限流。普通登录 access token 有效 15min，refresh token 最长 30 天、每次轮换、仅存 hash，可撤销；客户端放 Windows 凭据保护存储，不放渲染器 localStorage 或日志。默认每用户最多 2 个激活设备，设备随机安装 ID，重装/解绑需后台处理，不采集硬件指纹。

管理员独立角色与登录策略，正式公网后台强制二次验证或受控网络访问；普通用户 token 不能调用管理 API。服务端每次付费操作重新验证账号、会员时间、功能和额度；只靠 JWT 上的过期权益或客户端时钟不合格。

### 8.2 会员和额度语义

membership 是有效期及功能，credit grant 是独立的额度批次，两者分开。默认会员有效区间为 `[starts_at, expires_at)`，服务端 UTC 时间判定；界面按用户时区展示。账号停用立即拒绝新调用并撤销刷新会话；已有本地记录仍可读。

额度使用整数 `unit`，禁止浮点计算余额。每次发放一个带有效期的 grant；按最早到期优先预留。可用额度只计算当前有效批次的 `amount - revoked - spent - reserved`。已预留的到期批次允许为原调用结算；释放后的过期额度不重新可用。默认不自动滚存、不暗中透支、不因取消就保证零扣费。

建议内测人工发放 31 天会员和独立到期额度，实际赠送数量在 G04 决定。未开通付费不阻止本地解析、历史查看和导出；所有云模型/搜索操作仍需对应权益。

### 8.3 路由与请求

客户端仅提交角色别名、消息、受控工具定义、输出上限、task_id/attempt_id/request_id；不提交服务商 Key、任意上游 URL 或自定费率。自有 dsh provider adapter 对接 `contracts/openapi.json` 中的 `/api/v1/model-runs`，由服务端映射已验证的实际模型。适配必须覆盖流式文本、结构化工具调用、usage、错误和取消；不能仅演示纯文本就认定 Agent 兼容。

每账号同时最多 2 个付费模型请求，单账号未明用量记录达到 1 条时暂缓新请求，提示结算核对中。网关设置单请求输入/输出/时长、每天服务总成本和每用户成本保护；达到硬预算不调用服务商。平台预算保护与用户权益分别显示原因。

模型路由或费率更新生成新版本，已派发请求使用派发时快照；工具文本、图片、reasoning token 和缓存类别的计量方式在 G02 逐项用实际响应验证。不能把不同服务商同名 usage 字段直接相加。

### 8.4 预留、结算与幂等（必须实现）

1. 验证账号/会员/功能；校验请求体、路由和幂等键；估算输入（包含系统提示与工具 schema）并加输出上限，按固定费率形成可覆盖的预留单位上界。无法给出合理上界的模型/模态不上线。
2. PostgreSQL 事务中按到期顺序锁定有效 grant，检查可用额度与并发槽，写入 run/reservation/allocation；唯一键阻止重复 request_id。余额不足回滚全部操作，不向服务商派发。
3. 将 run 标为 dispatched 后派发。只有明确“尚未派发”的失败可释放后自动重试；网络不明不重新创建调用。
4. 收到最终 usage 后以服务端事务一次性结算：释放预留，写不可变 ledger，按实际单位扣减。重复终态/回调返回原结果，不能重复扣费。
5. 取消或断流不等于服务商停止计费。能够取得真实 usage 的按该用量结算；未知则标 `pending_usage`，保留预留并由核对任务查询。任务界面可先结束，账本状态独立。
6. 未知用量最多保留 72h；到期仍无可靠依据则释放用户预留，记 `waived_unknown`。后续迟到用量只记平台成本及差异，不追扣已释放的用户额度。每次豁免要有系统审计，不能删除调用记录。
7. 实际应扣超过预留时，用户最多扣原预留，超出记平台吸收；报警并暂停问题路由，修正估算后再开放。不能产生负可用余额或偷偷补扣其他请求。

`Idempotency-Key` 用随机 UUID，与 user_id 唯一约束，至少保留 7 天的请求 hash/结果元数据。同键同 body 返回既有 run；同键异 body 返回 409。服务重启后依靠数据库状态恢复，不依靠内存去重。request_id 和 provider_request_id 分列，用户取消/客户端重试不修改原记录。

### 8.5 额度换算与成本

费率快照以整数表示每 1,000,000 个计量 token 对应的 units：`billable_units = ceil(sum(tokens_category × rate_category) / 1,000,000)`。类别必须互斥，如 cached_input、uncached_input、output；reasoning 若已包含在 output 则只作子项，不再次计价。零用量允许零扣，不能每个类别独立向上取整放大扣费。

服务商实际成本另用币种、十进制定点金额和价格快照记录，不与用户 unit 混为一谈。搜索默认不扣用户 unit，在服务端计运营成本并限频；如果商业政策改为收费，先更新规则版本和展示，不能后台暗改。

前台用量展示单位、请求时间、任务、处理中/已结算/已豁免；不需要暴露所有原始 token 分类，但管理员对账必须能查。并发与幂等测试要求账本分录、批次余额和请求状态三者一致。

### 8.6 收费设计交付

C04 产出 `commercial-policy.md`：试用/基础/高频会员的功能和额度候选、退款与到期处理、服务支持、模型/搜索/服务器/支付渠道等成本、预算与限频。月费、额度数和利润率不在本 spec 编造为确定值。

决策使用每用户真实样本的 P50/P90 月成本及使用频次：可覆盖成本 = 含税实收减去税费、支付费用、变动服务与支持成本；不能以“模型单价便宜”直接证明订阅盈利。内测先人工权益，正式在线支付、订单、退款、自动续费、发票是后续单独规格，不由本包的管理员发额度接口替代。

## 9 管理后台、接口与数据基线

### 9.1 管理功能

用户列表与详情、创建邀请、启用/停用、会员有效期/功能调整、发放/撤销未消耗额度、用量/成本查询、待核对调用、错误分类和操作审计。额度调整不直接编辑余额字段：增加生成新 grant，减少只能撤销未使用且未预留部分；已消耗历史不修改。

管理写操作包含 reason、Idempotency-Key、expected_version；版本冲突返回 409 及当前版本。敏感改动显示变更摘要；审计含 actor、对象、变更前后元数据、时间、原因、请求 ID，不含密码、激活码正文、token 或文档。

### 9.2 接口边界

`contracts/openapi.json` 是产品自有控制接口 v1，包含邀请激活、登录/刷新/登出、当前权益、用量查询、模型 run 创建/状态/取消、搜索/正文、管理用户/会员/额度/核对。所有时间 RFC3339 UTC，ID 为 UUID，金额与余额单位在字段定义中固定；错误统一含 code、message、request_id、retryable、details。

模型 SSE 每事件有 event_id、run_id、seq、type、data；类型 run.created/text.delta/tool.delta/usage/final/error。工具参数增量必须聚合并通过 schema 后才可执行，不能执行半个 JSON。只有 final 才表示该模型流结束，账本可能仍 pending_usage。断线使用状态接口核对，不盲重连重发服务商请求。

本地接口只走受限 Electron IPC/产品宿主内部调用；不默认监听公网或 0.0.0.0。若候选插件必须本地 HTTP，只绑定回环、随机端口和单次随机认证，校验 Origin 和令牌，禁止任意网页调用。文件打开和另存为由宿主 broker 接收 ID，不允许渲染器直接访问任意系统路径。

### 9.3 数据表与约束

`data/local.sql` 与 `data/server.sql` 给出产品结构基线。上游会话库继续复用，产品只保存 upstream_session_id 引用，避免维护两份相互冲突的对话真相。所有 ID 不包含源文件路径或账号隐私。

本地：任务/attempt、文档及版本、段落与引用、产物、知识库关联/索引代、个人要求及修订、Office有效快照、领域包及版本、订阅计划及修订、来源订阅/文章/修订、调度运行、通知、迁移记录。服务端：用户/设备/会话、会员、额度 grant、模型 run、预留分配、账本、费率路由、管理审计及幂等记录。

管理激活码只在首次生成时返回；幂等重放不保存或再次返回该秘密，需新码时显式轮换。密码恢复和设备解绑接口见 `contracts/API-semantics.md`。

数据库约束必须配合应用事务。SQL 模板不能替代诸如“有效 grant 到期顺序锁定”“账本不可变”“状态迁移合法”“FTS 与向量一致”这些应用逻辑；对应测试已列在测试集中。初始 schema 不包括真实密钥和生产数据。

### 9.4 留存、删除及备份（D）

本地会话、文件和知识记录保留至用户删除；缓存默认 30 天、临时执行目录终态 24h 后清理（诊断保留需单独标志），删除先立即从检索和界面排除，再执行文件清理。共享对象按引用计数清理，不能删除仍被其他知识库或任务引用的对象。

服务端用量、审计默认留存 180 天，普通运行日志 14 天，不保留推理正文；实际留存政策在 G04 记录。全量数据库备份每日一次、保留 7 个日备份和 4 个周备份；每次发行前验证恢复流程。密钥使用环境/密钥存储，不写数据库脚本、客户端包或仓库。

本地升级前暂停任务并做一致快照；SQLite 采用 backup API/受控 checkpoint，不能只复制 WAL 活跃时的主文件。迁移失败恢复完整版本快照，禁止新旧 schema 混跑。向量可重建，原始对象和元数据不可依赖重新下载恢复。

## 10 V0.2 知识库完整规格

### 10.1 数据与导入

知识库包含名称、说明、分类和文档关联。行业、岗位、法规编号均非必填，通用名称、普通项目资料可直接使用。医药元数据作为可选字段，不通过系统提示词把所有问题改写为 QA/QC 问题。同一文档对象可关联多个库，文档每次内容变化生成新 document_version_id；相同内容 hash 可复用文件对象，但原始显示名、来源和业务版本分别记录。默认单库 1,000 个文档版本、总导入对象 5 GiB、最多 100,000 个有效 chunk；超过需分库或明确调整上限并重做性能验收。

导入状态依次为 queued → copying → parsing → chunking → embedding → indexing → ready，允许 partial/failed/cancelled。只有完成索引发布的版本参与检索；新版本失败时旧有效索引继续使用。UI 必须显示总数、就绪数、部分数、失败数及各失败原因。partial 版本只有在可用片段索引发布后才可供选择，默认 included=0；用户明确选择使用已读部分后置 included=1，检索必须同时满足 active generation、ready（或已允许的 partial）、范围和删除过滤，并提示未读范围。

首版知识库使用手动导入/更新，不默认后台监控任意文件夹。文件在外部修改后，由用户点击“更新版本”导入；模型不能自行认定哪个版本是现行。库中记录 source_type（个人/公开资料）、标题、机构、地域、文件编号、发布/生效/废止日期（未知为空）、业务版本、current/historical/unknown 状态和用户核对说明。

用户指定 current/historical 只是该用户的整理状态，显示“用户标注”；官方有效性不能仅根据上传时间推断。相同主题多版本互相冲突时，回答显示版本差异；默认检索 current 与 unknown，历史版本只有明确选择或比较任务才加入。

### 10.2 切块和本地嵌入

复用 V0.1 的 ParseResult。先按标题、段落、PDF 页、工作表/表格和幻灯片做结构边界，再按选定嵌入 tokenizer 切块。规格默认每 chunk 最多 350 个正文 token、相邻重叠 50；标题/路径等最多 80 token，前缀和特殊 token 后总输入不得超过 512。表格带列名/单元格区域，禁止把数字与行列标题任意分离。

嵌入默认本地 CPU，候选 `intfloat/multilingual-e5-small`，384 维；query/passage 前缀按模型要求（实际为 `query: ` / `passage: `），L2 归一化。模型 revision、tokenizer、推理后端、量化资产及 hash 在 G05 冻结。该模型是实施起点，不代表已通过本领域评测；更换模型、维度、切块或前缀必须生成新索引代并重建，禁止把不同空间的向量混在同一索引。

关键词侧使用 SQLite FTS5。中文用冻结版本的本地分词器预分词并保留英文缩写/数字/编号，不能声称默认 unicode61 已完成中文词法分词。向量侧在 100,000 chunk 上限内默认使用 float32 归一化矩阵 + 本地分块点积扫描，每批 4,096 行、TopK 维护在内存，不计算全矩阵笛卡尔积。完整快照同时保存有序 chunk_id 映射、model_hash、参数、校验和；这是有意选择的低运维方案，P95 不达标再用 ADR 换本地向量索引。

chunk_id 由 document_version_id、结构定位和切块参数 hash 确定，同版本重建不得随机漂移。索引采用 generation_id：新代 staging 写入 → 数量/hash/维度/定位检查 → 单事务切换 active_generation → 清理旧代。崩溃时旧代仍有效，孤立新代可回收；不得先删旧索引再开始长时间重建。

### 10.3 检索与回答

每次问答显式选择库/文档范围。先按库、版本状态和删除标记过滤候选，再分别关键词 Top30、向量 Top30，用 RRF `score=sum(1/(60+rank))` 融合；同一 chunk 去重，候选最多 10 个，默认送入模型最多 6 块及 8,000 上下文 token。范围过滤须在最终结果再检查，不能向量搜到其他库后直接展示。

回答流程保留查询、命中文档版本和引用；本地检索本身不计云模型额度，生成答案使用普通网关结算。引用必须指向检索所得实际片段，不把模型记忆包装成本地依据。对关键数字、义务和法规条文逐项挂引用；资料仅部分覆盖时说明。

“依据不足”不依赖一个拍脑袋的全局 cosine 阈值。G05 用固定的可答/不可答题校准证据规则和分数范围，保存 evaluation_version；无有效证据、来源矛盾或被删除时允许拒答或仅列出已知内容。知识库模式默认不混入网页答案；用户开启“补充联网”后，网页来源和本地来源分开显示。

### 10.4 更新、删除与恢复

更新创建新版本，用户选择取代现行或保留并列；切换 active version 与 active index 采用原子步骤。删除关联立刻排除该库检索；删除整个文档在同一事务标 tombstone 并排除所有相关库，再排队清理 FTS、向量代、解析缓存和不再被引用的文件。清理失败保留失败记录、重启重试；任何旧向量命中都必须经过 tombstone 检查。

全局删除同时使任务中该文档版本的原文入口失效，并清理引用摘录；同 hash 仍被其他有效文档引用时物理对象保留，但不能借已删除版本访问。历史回答已有文字不因删除而被篡改，引用卡显示“该资料已删除/不可访问”；不保留可被用户界面继续打开的已删除原文副本。备份可能仍含旧文件，删除说明必须如实告知备份到期清理规则；不把逻辑删除称为物理安全擦除。

### 10.5 V0.2 验收指标

使用至少 120 道已标注题：80 道可答（含中文、英文缩写、跨表格/页和版本问题），20 道无依据，20 道冲突/历史版本；开发集与保留验收集分开，至少 40 道保留题；120 题中至少 30 题为非医药通用项目/制度/办公资料，统计总体与子集，均按同一指标验收。领域和通用任务评审给出答案要点与允许引用的 chunk/位置，题目不得含未经授权的企业敏感材料。

默认验收目标：有明确金标准的检索 Recall@5 ≥90%；引用对象存在、位置可打开为 100%；引用确实支持对应关键主张 ≥95%；无依据题正确拒答 ≥90%；删除/范围隔离和原件保护为 100%。这些是验收目标，不是当前测试成绩；指标分别算分，不能用一个综合平均值掩盖关键失败。

## 11 V0.3 资讯采集、每日推送与调度

### 11.1 领域包、选择式订阅与来源（FEED-01—03）

平台维护版本化领域包（domain_id、version、名称、简介、主题、内容类型、默认选项、已验证 source_id/adapter_version、摘要规则、状态和完整性 hash）。通用采集/调度不写死主题或来源；未启用领域不会自动注入问答或办公。每个领域包的主题、内容类型必须有真实来源及样本覆盖，不能提供无内容的选项。

V0.3 至少交付一个通过 G06 的医药包，候选官方栏目为 NMPA/CDE/FDA/EMA；URL、RSS/选择器、日期、语言、访问条件均需实测。医药主题可含 GMP、质量体系、偏差/CAPA、变更、检验、验证、数据完整性；候选内容类型为法规/指导更新、技术与检查动态。只有确有可靠来源支持的选项才 published。第二领域只要求合成 fixture 验证可扩展性，不承诺其真实内容已上线。

用户流程：选领域 → 勾选主题与内容类型 → 设每日时间/时区 → 预览覆盖范围及样例 → 保存。可直接用建议选项，可选关键词；无需网址、RSS、Key、cron、正则或抓取配置。订阅设置与系统权限区分：Windows 通知关闭仍能生成站内日报。可暂停/恢复、修改、手动刷新，显示下次运行和最后状态。无已发布领域时明确无法新建计划，不伪造目录。

默认每账号在本机保存一个 daily 计划，多领域合并一份日报，每日自动通知至多一次；跨设备不做文件/配置同步，自动 AI 预算按服务端账户共享。多时段/多计划留后续。选项展开后的唯一来源总数最多 10；超限在保存前阻止并要求缩小主题，不静默丢源。不能以领域数重置调用次数或额度预算。

包随发行包预置；后续更新由平台发布受版本与完整性校验的数据包，内部调试可导入候选。包只能引用发行允许列表中的 adapter，不可携带脚本/动态执行模块。具体下载域名、完整性清单/签名方案在 G06 冻结；首期可随软件升级交付，不强制建设在线市场。已有修订包不可原地覆盖。

保存订阅创建 plan_revision，记录各领域包版本、主题/类型/关键词和 resolved_source_ids。一次运行固定该计划及包版本快照，不混入执行中更新。新增包版本提示更新并预览变化，用户保存后从下一合法执行点生效；移除/失效来源显式 partial，不能静默切换未知来源。旧版本撤回时暂停受影响源并提示重新配置。

每来源每日最多 50 候选条目，总共最多 10 个源；优先 RSS/公开列表与正文，不绕过登录/验证码/付费墙。同域最多一个并发、间隔 ≥2s；403/429 退避。每 adapter 有列表/正文/日期/canonical/终止规则和 fixture；G06 至少冻结 4 个可用官方栏目。普通用户不配置抓取器；提议新网址作为平台待验证需求。

配置对象见 `contracts/personalization-and-subscriptions.schema.json`，事务和应用层校验见 `contracts/personalization-and-subscriptions.md`。

### 11.2 增量、去重及修订

保存 source_id、canonical_url、published_at（可空）、discovered_at、fetched_at、title、body_hash、内容修订号及状态。canonical 只去来源明确认可的跟踪参数，不全局删 query。默认主去重键为 source_id + canonical_url；相同 URL 正文 hash 变化产生新 revision，标题小变不重复推送，实质变更可推送“更新”。

跨源转载用规范正文 hash/相似度形成重复组，保留各来源而以官方原文为展示主条目；不能凭相似标题删除不同法规文件。发布时间未知时显示“未取得发布时间”，排序可用发现时间但必须标明；不把抓取日期伪装成发布日期。

每源 watermark 为上次成功扫描时间/游标，并保存重叠回看窗口默认 7 天；断点分页与 article 唯一键保证重复扫描无害。来源失败不前移该源 watermark；其他成功源可形成 partial 资讯摘要，并注明缺失来源。摘要失败时保留已采集条目，下次仅重试摘要，不重新制造文章。

### 11.3 相关性、摘要与额度

主题、内容类型和摘要字段取自当次领域包及计划快照；通用层不写死医药主题。先按选择规则/关键词筛选，再对候选合并进行模型结构化摘要，避免每条文章单独调用。摘要包含“发生了什么、影响对象、可能需关注的工作、原文链接”；推断用语不能写成法规要求。

本地解析/采集不扣模型额度；自动摘要按普通网关扣额度。默认每日资讯模型预算在当日第一次自动资讯调用前快照可用额度，取其 5%（整数向下取整），另受平台绝对上限（G04/G06 冻结）约束，每天最多 2 次模型请求；不足时仅展示标题/摘要原文和来源，显示“额度不足，未生成 AI 摘要”，不清空历史。用户手动重试明确提示新消耗。预算和请求计数在服务端按账户、Asia/Shanghai 业务日持久化并发控制，跨设备/重启共享；日程展示时区变更不重置该预算。未冻结绝对上限时不开放自动 AI 摘要。

### 11.4 调度的精确定义

默认时区 Asia/Shanghai、每日 09:00，可改；时区使用 IANA 标识，数据库时间 UTC。程序运行包含前台和托盘；完全退出不执行，不默认安装系统服务或 Windows 计划任务。

每个日程执行绑定不可变的 plan_revision；日程时间不变但主题更新也必须保存新的计划修订。每个日程产生唯一 `schedule_id + logical_date + schedule_revision`，logical_date 按日程时区。启动时若错过一个或多个应执行点，合并为一次 catchup，覆盖从各源最后成功 watermark 到当前时间的范围，并显示覆盖窗；不逐天补发旧通知。已成功的当天日程不因重启或时钟回拨再执行。

修改时间/时区创建 schedule revision；仅修改内容也创建 plan revision，当前 schedule 的下次 run 采用新计划修订；新 revision 从下一合法执行点生效，不自动重复当天已完成内容。夏令时不存在的时间顺延到当天首个合法时刻，重复时刻只执行一次。运行中退出：下一次启动回收过期 lease，重用 run 的业务唯一键继续，文章和通知幂等。

调度执行有本地持久 lease，默认 10min、每分钟心跳；采集与摘要分阶段写进度。确定暂时故障按 1min/5min 最多两次重试；超过当日窗口仍保留 failed/partial，下一次运行从成功游标继续。用户手动“立即刷新”生成独立 run，但复用文章去重，不修改今天是否已通知的唯一键。

### 11.5 通知与运行记录

默认站内资讯收件箱 + 可关闭的 Windows 通知；同逻辑日最多一条自动通知，partial 通知注明覆盖不完整。通知点击只打开产品内摘要 ID，协议处理不得允许任意路径/命令。系统禁用通知不算业务失败，内容仍在收件箱。

运行记录显示计划/实际时间、范围、来源成功/失败数、新增/修订/去重数、摘要和额度状态、下次重试。G06 用测试时钟/模拟故障验证所有分支，再完成至少 14 个自然日的来源观察；日历观察可与其他开发工作并行，不能用“跑过一次”替代稳定运行。

## 12 V0.4 办公工作流

### 12.1 公共操作协议

所有工作流为：选输入/模板 → 提取资料与缺失项 → 展示可理解的操作计划 → 执行确定性生成器 → 内容/结构/数字检查 → 渲染预览 → 保存新副本。用户普通自然语言提问无需每次多余确认；涉及选择修改页/范围或缺失关键字段时才在业务 UI 补充信息。

计划字段为 input_version_ids、template（template_id/version）、operation、targets、steps、allowed_changes、output_format、missing_fields；V0.4 起附 effective_preferences 不可变快照。各步骤 source_ids 关联真实资料，执行后形成产物 source_map；字段以 OfficePlan Schema 为准。生成器不执行模型给出的任意 Python/PowerShell/JS。关键数据来自可追溯输入或确定性计算；无来源字段用“待补充”，不填假日期、审批人、批号、标准限值或结论。

模板文件作为版本化对象，可导入并预览；内容控件/占位符规则在模板 manifest 中定义，首版模板不是任意文件都能自动适配。字体优先随包的可再分发中英文字体，缺字和替换需检查。用户自行提供的企业字体按其实际授权和安装状况处理。

### 12.1a 个人要求与模板（PREF-01—03）

本地“常用要求”支持创建、命名、复制、编辑、删除、选用和显式设默认；无默认也能直接开始。每次编辑创建不可变 revision；删除仅阻止新选用，历史任务保留其使用快照。默认上限 50 个有效配置；名称 1—60 字，描述 ≤500 字，自然语言补充 ≤4,000 字。预设与个人要求分开，不能自动替换用户已保存内容。

通用字段：受众、语言、语气、篇幅、术语表、必须包含/避免内容。Word：标题层级、支持字体/字号、纸张/页边距；Excel：小数位、单位、日期显示和工作表格式；PPT：风格、颜色、支持字体、页数和固定版式。各字段受格式能力及模板 manifest 校验，初期不支持任意宏、脚本、任意 CSS 或像素级全能设计。V0.4.1 启用通用/Word/Excel，PPT 字段随 V0.4.2 开放；旧 profile 在新版本按 schema 迁移，不静默改值。

可关联 template_id/version 和默认 kb_ids；每个任务可解除或覆盖。开始生成时重新校验模板、库和文档的访问状态；明确显示将使用哪些库，用户选择后按 active generation/有效版本检索，只发送必要片段。删除库或模板失效时停止对应引用并提示选择替代；不得自动扩大范围到全部库。

有效优先级：硬性权限/原件保护/格式支持边界/模板锁定约束 ＞ 当前任务明确要求 ＞ 选中个人配置 ＞ 模板默认 ＞ 已选领域预设 ＞ 软件默认。自由文本要求先结构化为支持字段，冲突列出采用值与原因；影响内容、页数或模板的未决冲突返回 needs_input。不可满足时给出可执行选项，不能静默忽略、悄改锁定模板或虚构来源。普通一致任务不反复弹确认。

本次要求编辑默认只影响本次，点击“保存为常用要求”才新建/更新个人配置。每 attempt 保存 EffectivePreferences：profile_id/revision、domain_id/version（可空）、模板版本、resolved_fields、字段 provenance、冲突处理、已解析知识范围及 generation、快照 hash。任务执行与重试使用快照；恢复已删除资料不能绕过当前权限，改要求重新运行须新 attempt。OfficePlan 1.0 兼容增加可选字段，V0.4.1+ 调用强制附该字段，V0.1 旧计划仍可解析。

可复用偏好用于确定性排版与任务提示，模型可能无法完全遵循内容语气；必须检查可验证字段并提示未满足项。单位/日期/页数/字号等确定性规则做结构或渲染检查，不把保存偏好解释为本地微调、模型记忆或自动训练。

### 12.2 V0.4.1 Word

默认支持：标题/段落/列表/普通表格、页眉页脚基础字段、图片、模板占位符替换；通用场景为报告、纪要、培训和资料对比；首个领域包增加 SOP 摘要、质量报告初稿。复杂浮动文本框、嵌入对象、未知字段和未经支持的修订不做全量保真承诺。

修改已有 DOCX 时先列出可改段落/表格范围，按 part/对象修改副本。未选范围如有结构性变化必须标差异，不能静默重排。输出附内容来源表与缺失项；导出前重新读取确认段落/表格存在，生成预览检查分页、缺字、表格溢出、页眉页脚和页码。预览引擎不是原生 Word，UI 标明实际检查方式。

### 12.3 V0.4.1 Excel

默认支持：选择工作表/范围、列类型与缺失值处理、去重、日期/文本规范化、筛选汇总、描述统计、普通折线/柱形图；使用固定函数白名单和区域检查。默认单元格区域受 V0.1 上限约束，输出另建工作簿或新副本。

模型给出的计算计划必须由确定性代码或实际电子表格计算引擎执行；LLM 心算不能成为正式结果。记录公式、数据范围、空值/异常值策略、小数精度和单位。公式支持集在 G07 冻结，至少覆盖 SUM/AVERAGE/MIN/MAX/COUNT/IF 及简单算术；不支持的公式或外链标为未验证，不能把旧缓存值当重算结果。

验证至少包括固定输入的独立期望值、公式单元格重算结果、图表数据区域、日期/百分比/中文显示及除零/空值。CSV 导出对以 `= + - @` 等开头的文本防公式注入，并允许用户明示导出数据类型，不能把真实数值负号全当危险字符损坏数据。

质量统计中的 RSD、置信区间、趋势或控制图只有在定义了公式、适用前提和样本 oracle 后纳入模板；V0.5 可增补，不能因为面向 QC 就默认已具备所有检验判定算法。

### 12.4 V0.4.2 PPT 生成

默认一次 5—30 页，提供封面、目录、正文、双栏、表格、图表和总结等固定版式；以用户批准的提纲/选中材料生成。每页保存 slide_id、来源段落/数据与关键数字映射；内容不足减少篇幅或保留待补充，不为凑页数制造事实。

生成器使用模板占位符、文本量上限、表格/图片尺寸约束；至少两轮“结构检查 → 实际渲染 → 溢出/遮挡检查”。可自动调整字号/分页须在模板范围内，不能降到不可读字号。默认中文正文不低于 18pt、标题不低于 24pt，模板另有严格规范时采用其规范并记录。

交付 PPTX 与逐页预览，渲染失败或部分页缺失标未完成检查。图表必须来自确定性数据，图片使用用户资料或可合法使用资源；没有检索/许可就不自动抓取未知版权图片。

### 12.5 V0.4.3 已有 PPT 修改

用户选择页和对象；白名单先支持现有文本框内容、普通表格单元格、明确占位符图片替换。更换主题/整稿重排属于独立“生成新稿”，不得混入精确修改。图表、SmartArt、音视频、动画、OLE、复杂组合形状先检测；未支持对象不自动展开重建。

修改前建立 OOXML part/关系映射和页预览，修改后比较：原件 hash 必须不变；未选页的 slide XML、关联媒体及关系应一致。共享母版/主题变更可能影响未选页，因此精确修改默认禁止更改共享 part；确有需要则告知改为整稿任务。ZIP 重打包字节不同不等于内容变化，比较解包后相关 part；XML 序列化差异应规范化后比较并保留差异报告。

如生成库无法保留未选对象，用针对性 OOXML 修改或拒绝该操作，不可整稿读写后只凭截图相似宣称保真。指定页还需检查文本、坐标、字体、图层和渲染效果。原文件含不支持对象时可允许不触达其 part 的局部修改，但必须有专门 fixture 证明保持；无法证明则阻止该路径。

## 13 V0.5 领域调优与效果管理

建立至少 30 个脱敏真实代表任务，其中至少 10 个跨领域通用知识/办公任务，其余首个医药场景覆盖 SOP 对比、偏差材料整理、CAPA 初稿、QC 表格汇总、法规检索及培训 PPT；每项记录输入、操作、期望内容、证据、禁错项和耗费。对应领域专业人员评审领域模板中的术语和依据，未经审核的模板显示草稿。

优化优先级为：原件/数字/引用正确性 → 任务完成率 → 可用性 → 耗时和成本。模型路由、提示词、chunk、模板和解析器均版本化；候选方案在相同保留集与机器上对比，至少记录任务成功率、支持性引用、拒答、P50/P95 延迟、每成功任务成本和用户人工修订量。

允许通过提示词、工具 schema、检索和模型路由优化；不默认训练或上传用户文档。优化须不破坏原件保护、范围隔离、账本一致性和关键数字正确性；任何关键回退使候选不能发布，即使平均速度更快。

## 14 非功能性指标与可观测性

### 14.1 Windows 及硬件基线（D → G00/G03 冻结）

Windows 10 22H2 x64 和 Windows 11 24H2 x64 作为首轮测试基线；Electron/依赖能否运行、组织镜像限制和实际支持构建在发行清单写清楚。支持 Win10 是产品兼容范围，不意味着微软系统生命周期由本产品保证。其他 Win10/11 构建不能在未测时一概宣称支持。

最低参考机：4 核 x64 CPU、16 GiB RAM、SSD、至少 8 GiB 可用空间，另留用户资料空间；无 GPU。构建机和测试机分别记录 CPU 型号、系统补丁、内存、存储、区域、字体和网络。安装包大小、完整运行资产占用以实际清单为准；超过 8 GiB 时调整最低空间及安装前检查。

| 文本解析 | 10 MiB/100 页文本 PDF fixture，本地 | P95 ≤30s；OCR 不混入该指标 |
| OCR | 20 页清晰 200—300dpi 中英印刷扫描，CPU | 总耗时 ≤180s 的初始目标；G00 必须实测校准 |
| 知识检索 | 100k chunk，384 维、相同参考机、热查询 50 次 | 检索 P95 ≤2s，不含模型生成 |
| 取消 | 点击后停止新调度，本地 worker 退出 | UI ≤300ms；协作停止 ≤5s，强杀回收 ≤10s |
| 本地内存 | 20 页 OCR 与 100k chunk 检索分别测，不叠加 | 产品进程组峰值 ≤4 GiB；超限分批处理 |
| 网关 | mock 服务商、50 并发、非流式控制请求 | P95 ≤500ms，不含外部推理；无越权/超扣 |

未达性能目标时记录瓶颈、调整算法或经 ADR 修订目标，不得伪报通过。云首 token 与总生成时延单列实测，不用本地目标对服务商 SLA 作保证。

### 14.3 安全和稳健性

包完整性检查、受控依赖/资产 hash、HTTPS、服务端凭据、最小管理员权限、CSRF/跨源策略、登录限流、错误脱敏、SQL 参数化、IPC 白名单、路径规范化、导入压缩包上限、网页 SSRF 和提示注入测试均为发行必查。默认不自动执行宏、从文档启用外链或调用未知插件。

用户级本地数据用 Windows 文件权限隔离；本基准不承诺完整磁盘加密。凭据由系统保护，文件加密/企业 DLP 后续独立设计。不能为了排障自动提升权限或修改用户原目录 ACL。

### 14.4 观测和诊断

客户端带 task/attempt/operation/request correlation IDs；服务端记录 route、状态、时长、token 类别、预留/扣减/平台成本和错误。指标包含安装失败率、任务完成/partial/取消率、解析失败页、待核对用量数、余额不变量异常、搜索来源失败及资讯漏执行。

诊断导出默认只含环境版本、ID、步骤、错误和脱敏堆栈。用户勾选附加样本文件时列出具体文件，不能默认上传。日志不含 prompt、正文、access/refresh token、激活码、模型 Key 或完整本地源路径。崩溃收集器亦遵守同样规则。

## 15 自动化与手工测试策略

### 15.1 测试层次

单元测试用于额度公式/事务边界、状态迁移、日期调度、canonical 去重、定位和数字计算等易出错业务；集成测试用临时 SQLite/PostgreSQL、模型/搜索 mock 和真实文件引擎；端到端测试使用最终用户安装包在干净 Win10/11 x64 上运行。截图/渲染检查及专业答案评审不能用纯单元测试替代。

mock 覆盖 token/工具分片、乱序或重复结束、断线、已派发超时、usage 缺失、取消后 usage、429、恶意网页、时间跳跃和进程崩溃。真实模型/搜索另做小额冒烟，保存脱敏元数据与费用；不能用 mock 声称实际服务商兼容。

### 15.2 固定 fixture 与 oracle

`acceptance/fixture_manifest.json` 列出需创建/收集的样本组、内容要求、授权及 oracle。初始状态为 required，不是已附带真实文件。C00/C02 必须填充真实二进制 fixture、hash 和期望提取结构；验收脚本检测未完成项即失败。不得拿文件名后缀伪装格式。

每种格式至少有正常中文、英文/混排、边界/损坏、超限/复杂四类；扫描样本有逐字人工校对文本、页码和区域。清晰印刷 OCR 用字符错误率 CER（替换+删除+插入 / 真值字符数）≤5% 的目标；复杂/低清案例要求正确提示和逐页状态，不套用清晰集成绩。

Excel oracle 用独立期望数字和公式类别，不能调用与实现完全相同的函数生成真值。PPT 修改 oracle 比较未选 part 及媒体并人工看图。原件保护先记录源文件及源目录可写性/hash，执行攻击性计划、取消、异常和升级后再核对，不能只检查正常流程。

### 15.3 准入与退出

每任务：实现 → 对应测试 → 结果/版本/证据 → 自检差异 → 标完成。周期完成：三项工作包及集成场景通过、无阻断缺陷、更新风险/决策。发布完成：当前及此前版本全部 P0 通过、无严重账本/原件/越权/泄露问题、真实 Windows 和发行包验证、回退材料齐全。

P0 测试不得通过“暂不支持”直接豁免用户已确认能力。不可自动化的用例标 manual 并记录执行人和截图/检查表；跳过和未运行不等于通过。旧版已通过用例在升级、依赖或公共模块变更后运行相关回归。

### 15.4 指标口径

任务成功率只统计业务目标达成且检查完成的任务，partial 单列；取消不当成功。准确性分为提取正确性、关键数字正确性、引用支持性和答案要点，不用一个含糊“准确率”。性能给出机器、样本、样本数、P50/P95；成本按成功任务及失败消耗分别统计。

## 16 构建、安装、更新与回退

Windows x64 发行构建在原生 Windows x64 CI/构建机完成，使用冻结锁文件和受控资产。可重复构建指相同来源/依赖得到功能和内容一致的包；时间戳/签名导致二进制 hash 不同须可解释，不能无依据保证逐字节一致。

默认 per-user 安装，安装/运行不要求管理员；支持中文用户名、空格路径、无 Node/Python/Office/LibreOffice 的干净环境。依赖若需要系统组件应安装前检测并通过受控流程处理，禁止把失败转嫁为用户手动装开发工具。

V0.1 手动下载/安装更新，不连接上游更新源；更新包来源和 hash 可核对。生产发行优先代码签名；邀请内测若采用未签名包，G03 记录分发方式、发布者核对及系统提示，不能宣称无 SmartScreen 提示。自动更新以后需单独验签、分渠道、灰度和回滚验证。

升级流程：检查无活动写任务 → 备份 → 版本与磁盘检查 → 更新程序 → 数据迁移 → 冒烟 → 标记成功；失败恢复程序与数据库/对象的兼容快照。安装回退不能只换旧 exe 而留下新版不兼容数据库。卸载默认保留用户资料并明确提供可选删除；原始文件夹永不纳入卸载清理。

发布包交付：安装文件、SHA256、发行清单、开源说明/第三方 notices、版本说明、支持范围、已知限制、迁移/恢复指南、测试报告、商业政策版本及问题反馈入口。内测用户数默认先 5—10 人再扩大到 20—30 人，以成本和失败率判断；这些为运营建议，非技术硬限制。

## 17 执行工作包与需求追踪

工程包 `tasks.json` 是冻结后的工作包执行清单；每项有 ID、周期、估算、依赖、需求编号、实现步骤、产物和验收用例。计划设计变更先更新生成器并重新生成清单，实际完成状态与测试成绩写入独立报告，避免重建计划覆盖执行记录。`test_cases.json` 是测试源；覆盖关系双向校验。第 22 节的自动生成表用于人工扫描，不另行维护第三份任务清单。

原 PRD 编号 BASE/FILE/WEB/ACC/ADM/OPS 原样保留；新增 ARCH、KB、NEWS、OFF、NFR、REL、EVAL、BIZ 编号只补充规格，不改变原编号含义。原 T01—T15 与详细测试的对应见追踪表。所有引用只说明计划覆盖，实际通过状态写入独立测试报告。

### 17.1 每项任务的定义完成（DoD）

代码与配置可运行，未把 TODO/假返回写成正式能力；契约与迁移同步；对应自动/手工测试完成；失败分支和日志已核对；原件/余额/来源/权限不变量没有回退；输出和 Windows 证据真实；更新文档/版本/许可证及新发现风险。仅“页面可以打开”不能标整个工作流完成。

### 17.2 AI 编程助手执行约束

每次选一个依赖完成的工作包，先读本 spec、该任务、对应契约和测试。汇报输入/输出、修改范围和验证结果；实现接口前检查实际上游 API，不创造不存在的插件接口。发现规范冲突时提交 ADR/问题记录，继续不受影响的工作；不得默默变更已确认需求或一次实现整个路线图。

合并前核对本任务的新改动和关联风险，不因发现无关历史问题无限扩展任务。发现会破坏原件、额度、凭据或输出真实性的严重问题必须先修复或阻止发行。默认不自动部署、发送邀请或开启收费；本规格授权的是实施计划，实际发布动作遵守届时用户指令。

## 18 变更、缺陷与风险管理

规范优先级：用户已确认决定 → 本 spec 明确条款 → 产品契约 → 实现。契约与正文矛盾时必须修正并增加测试，不能让开发者自行选方便的一边。默认值变更使用 `acceptance/ADR-template.md`，说明触发原因、方案、影响的任务/测试/数据和回退；重大范围变更提高文档版本。

缺陷级别：S0 原件损坏、越权/凭据泄露、系统性超扣或虚构依据；S1 核心流程不可用/数据丢失；S2 局部功能失败有替代路径；S3 轻微界面问题。S0/S1 不能带入邀请版；S2 必须明确是否违反 P0，违反则仍阻断；S3 可列已知限制并排期。

主要风险及处理：

| 风险 | 触发信号 | 处理 |
| --- | --- | --- |
| 上游变化快 | 候选 API/插件不兼容 | 固定提交，集中补丁，升级作为独立验证 |
| Windows 引擎/字体/权限 | 干净机转换或 OCR 失败 | C00 提前测完整调用链；不靠开发机环境 |
| 订阅成本失控 | 循环工具调用/未知用量/高频资讯 | 逐调用预留、任务步数、用户/平台预算、核对阻断 |
