# QualityOffice AI 开发启动说明

版本：v1.0；日期：2026-10-22。配套需求文档 v0.3、开发 Spec v1.2。

这个补充包把已有开发规格接到 Cursor / Codex 的实际工作流程。它包含协作指引和模板，不包含已经检出或验证的 dsh 源码。

## 1. 你现在怎样放置

将 ZIP 中的 `AGENTS.md` 和 `docs/` 直接复制到当前 `qualityoffice-ai` 文件夹下，不额外套一层“开发启动包”目录。复制后，根目录能同时看到 `AGENTS.md` 与现有的 `开发Spec.md`、`tasks.json`。

如果原来已有同名文件，先保留原文件并合并内容，尤其不能覆盖已有上游 `AGENTS.md`。本包不改写现有 README、规格、任务、测试或数据库文件。

| 文件 | 用途 | 使用方式 |
| --- | --- | --- |
| `AGENTS.md` | 两个编程工具的共同规则与资料入口 | 放项目根目录，保持精简；启动时确认工具实际加载 |
| `docs/START-HERE.md` | 本说明 | 先看一次，后续按需要更新 |
| `docs/progress.md` | 实际进度和跨工具交接 | 每次任务或交接后更新，首次使用尚无完成记录 |
| `docs/review-policy.md` | 统一审查标准 | 开发自检与独立审查共同使用 |
| `docs/prompts/01-initialize.md` | 第一次给 AI 的任务 | 将正文复制给 Cursor 或 Codex |
| `docs/templates/work-package-report.md` | 工作包实际报告模板 | 复制到 `docs/reports/`，填事实和证据 |

当前不用手工创建前后端代码骨架，也不用先填写模型、插件或运行库的猜测版本。

## 2. 第一次让工具做什么

用 Cursor 或 Codex 打开整个 `qualityoffice-ai` 文件夹，在新会话中粘贴 `docs/prompts/01-initialize.md` 的内容。

第一轮检查现有文件与 Git 状态、建立工程接入方案、执行 W00-1 能完成的验证及记录。上游 commit、插件依赖和许可证要查真实来源；需要你本地 Windows 的步骤应实际运行或明确留待执行。

这里建议一次只启用一个写入工具。首轮完成后，再让另一个工具按 `docs/review-policy.md` 独立检查实际 diff 与证据。

## 3. 正式源码怎样接入

`qualityoffice-ai` 最终作为产品仓库名称；它应保留官方 dsh 的上游历史并记录固定提交。实际采用 fork 或其他保留历史的派生方式，由 W00-1 检查真实仓库后确定。

如果当前只有文档，不要对非空目录直接执行 `git clone ... .`。让工具先检查 `.git`、是否已有上游代码和未提交改动，再采用临时目录准备源码并迁移资料的方式。避免删除或清空现有目录。

进入正式源码仓库时，推荐将原开发基准包的全部内容整体移入 `docs/spec/`：包括两个生成脚本、检查脚本、Spec、JSON、`contracts/`、`data/`、`baseline/`、`acceptance/` 及清单。整体移动使包内脚本的相对路径保持一致。本补充包的 `AGENTS.md` 保留在项目根目录，进度与审查文件仍放 `docs/`。

迁移后，更新根 README 的入口和 `docs/progress.md` 的规格位置；运行 `docs/spec/validate_spec.py` 检查结构。若基准仍在根目录，则运行根目录的同名检查脚本。具体 Python 启动命令按本地环境确认。

不要机械搬动 dsh 源码来迎合预先画出的目录；遵循所选提交的实际工程结构。

## 4. 每个工作包的执行过程

1. 读进度、任务、相关规格、契约与测试，确认依赖。
2. 列必要改动与验证方式，实施当前已授权任务。
3. 运行对应检查；记录真实通过、失败与未执行项。
4. 用报告模板保存结果，更新进度并检查 diff。
5. 按统一标准审查，修复有证据的缺陷；形成可追溯提交后交接。

首次 C00 顺序：W00-1 候选基线与集成清单 → W00-2 Windows 运行引擎 → W00-3 受控执行与原件保护。不能用“文档结构检查通过”替代这些工作包的实际完成。

## 5. 什么属于开发事实

- 需求/Spec/计划清单描述做什么；真实报告、代码、构建包和检查记录说明做到哪里。
- 使用 `docs/progress.md` 交接，不依赖另一个工具能看到聊天记录。
- `docs/reports/` 保存实际任务与验证报告，建议以工作包和日期命名；敏感原始日志另作受控保存。
- 基准包自带的 `validation_report.json` 属于文档结构检查，不是 Windows 产品测试报告。
- `.env.example`、CI 和运行命令在源码接入后按真实工程添加；保留上游配置，再补产品差异，不提前猜依赖版本。

## 6. 确认工具读到了规则

首次会话让工具先说明加载的指引文件、规格位置和当前任务。若没有读取 `AGENTS.md`，显式要求读取，并检查是否打开了正确的项目根目录、是否存在上游或全局覆盖规则。需要时新建会话再核对。

两个工具的官方文档均支持使用 `AGENTS.md`。本包只维护一份共同指引；将来确有 Cursor 专用需要再增加 `.cursor/rules/*.mdc`，避免复制整份规格造成分歧。

参考：

- [Cursor Rules](https://cursor.com/docs/rules)
- [OpenAI 官方 AGENTS.md 指引](https://developers.openai.com/codex/guides/agents-md/)

## 7. 现有开发计划的地位

本包补充开发流程，不改变 Spec v1.2 的 67 项需求、45 个工作包、153 条计划测试或 33 周估算。工程初始化及真实验证耗时记入对应工作包，必要时按 Spec 的重估规则调整计划。
